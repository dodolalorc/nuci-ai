# Nuci AI 产品改进计划

## 1. 结论与定位

Nuci 应收敛为“本地优先的网页知识采集助手”，而非同时承担书签分类器、摘录工具、页面摘要器和知识库。核心价值是让用户用一次明确动作，将一篇网页或一个选区变成可回看的知识条目。

唯一主路径：**网页 → 快速保存 →（AI 可用则增强）→ 知识库回看**。

深度整理、片段收藏、书签推荐和历史书签迁移均为二级能力，只能从主路径的更多操作或管理台进入。

## 2. 信息架构与体验

| 入口 | 只做什么 | 不做什么 |
| --- | --- | --- |
| 页面悬浮按钮 | 默认一键快速保存；菜单提供保存选区、深度整理、打开知识库 | 不同时展示两套采集面板 |
| Popup | 最近保存、今日统计、打开知识库和设置 | 不再承担主要归档流程 |
| 知识库 | 搜索、筛选、详情、编辑、重试 AI、归档 | 不混入书签迁移向导 |
| 深度整理 | 调整正文范围、生成/编辑结构化笔记、保存 | 不与快速保存共享未定义的中间状态 |
| 设置/高级工具 | 模型、备份、书签归档、历史书签迁移 | 不干扰首次保存 |

快速保存的状态必须稳定：`抓取中 → AI 整理中（或本地保存）→ 成功/失败`。AI 不可用时仍保存正文和基础元数据，显示“已保存，等待 AI 整理”，而不是把一次成功保存标记成失败。

## 3. 当前审计发现

1. **两套知识数据并存**：`KnowledgeItem`/`knowledge-items` 与 `KnowledgeRecord`/`knowledge` 存储不同字段；书签确认后写入的是后者，快速保存写入的是前者，用户在不同页面会看到不完整的数据。
2. **正文提取重复三次**：`contentExtractor.ts`、`contents/capture/extract.ts` 和 `background.ts` 的注入脚本各自维护选择器、噪音规则和截断策略，结果会随入口不同而不同。
3. **入口职责冲突**：`FloatingButton.vue` 同时承担悬浮球、菜单、快速保存、深度保存和页面控制；`page-capture.ts` 又有侧栏与 AI 整理状态，用户会遇到两个“深度/AI”路径。
4. **后台文件过大且协议弱类型**：`background.ts` 既做路由又做书签、片段、AI、知识库业务，消息 `type` 多为裸字符串，payload 使用断言，改动容易静默失配。
5. **数据正确性风险**：快速保存忽略前端传来的标题/正文而始终重新读取活动标签页；页面切换时可能保存到错误页面。`update` 接收任意字段，内部字段可被覆盖。
6. **生命周期与性能风险**：页面侧栏通过设置 `html/body` 的 `marginRight` 影响宿主站点，但需要确保关闭、刷新、异常时完整恢复；多个内容脚本也增加了挂载与状态分裂风险。
7. **质量门槛缺失**：目前只有 typecheck/build 脚本，没有测试脚本、格式化脚本和可重复的关键流程验收。

## 4. 分期路线图

### Phase 0：止血与可观测性（优先）

- 建立统一消息协议、错误码和用户可见状态；记录不含敏感信息的失败原因。
- 为保存、AI 解析、存储迁移和正文提取加入单元测试；补充 `lint`/`format:check`/`test` 脚本。
- 规定页面状态清理：关闭侧栏、卸载、异常时恢复宿主网页样式。

验收：未配置模型、AI 超时、空正文、受限页、刷新页面均有明确结果；`typecheck`、测试与构建可重复通过。

### Phase 1：统一领域模型与采集链路

- 确定唯一实体 `KnowledgeItem` 与唯一存储键，加入 `schemaVersion`、来源、正文、处理状态、AI 结果和时间字段。
- 把旧 `KnowledgeRecord` 迁移到该实体；备份文件定义版本和迁移函数，迁移可重复执行。
- 产出唯一 `pageExtractor`，由内容脚本调用；背景页只接收已验证的提取结果，不再注入第三套提取逻辑。
- 设计“同 URL 再保存”规则：默认更新已有条目并保留用户编辑，或明确提示创建副本。

验收：任意入口保存后的数据都在同一个知识库可见；同一页面的正文和摘要输入一致；旧备份可导入。

### Phase 2：收敛用户体验

- 保留一个页面内主悬浮入口；快速保存为点击默认动作，二级菜单只保留选区、深度整理、知识库。
- 把深度整理抽成独立 feature 和状态机，复用统一草稿；去除并行的“AI 页面整理”实现。
- Popup 简化为状态与导航；书签归档移动到“高级工具”。
- 统一术语：采集、整理、知识条目、书签归档；避免“收藏夹/内容整理/知识记录”指向同一概念。

验收：新用户 30 秒内可完成一次保存；一次操作不会产生重复条目或不明面板；无模型也能完成核心闭环。

### Phase 3：可靠的 AI 与高级能力

- AI 服务使用结构化输出校验、重试策略、输入预算、取消请求和降级结果；每个 AI 任务持久化状态。
- 知识库支持全文搜索、标签/来源/日期筛选、详情编辑和 Markdown/JSON 导出。
- 历史书签迁移提供范围选择、预览、确认、操作日志与撤销；不得自动修改用户书签。

验收：AI 返回非 JSON、字段缺失、超长页面与中途取消均不会损坏条目；批量书签操作可审计和撤销。

## 5. 不做清单

- Phase 1 前不新增模型供应商、云同步、协作分享或复杂自动化。
- 不删除旧数据；先迁移、校验、保留回退窗口，再移除兼容代码。
- 不用“更多按钮/更多面板”掩盖流程不清晰的问题。
