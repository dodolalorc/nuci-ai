# Nuci AI 代码审核规范

## 审核顺序

按 P0（阻断）→ P1（本迭代修复）→ P2（记录优化）输出。每条问题必须包含文件/行、触发条件、实际影响和最小修复建议；没有可靠问题时明确写“未发现阻断项”。

## P0：必须阻断

- API Key、用户正文、选区或书签数据被记录、上传或导出到非预期位置。
- 未经用户确认创建/移动/删除浏览器书签，或批量操作没有预览和撤销信息。
- 存储结构变更会覆盖、丢失或无法读取既有数据，且没有迁移/备份兼容。
- 消息 payload 未校验即用于持久化、DOM 操作或 AI 请求，造成跨标签错误保存、崩溃或注入风险。
- AI 响应解析失败会破坏已有知识条目，或保存成功被误报为失败。
- 内容脚本在关闭/卸载后遗留宿主页面的 style、margin、监听器或遮罩。

## P1：本迭代修复

- 同一领域存在重复实现或存储真相来源；尤其是正文提取、知识条目、模型配置、消息类型。
- 同一 URL 的重复保存策略不明确，或并发保存会产生不可预测结果。
- 后台路由包含业务逻辑、组件包含持久化/AI 编排，导致不可测试的超大文件。
- 未配置模型、受限页面、空正文、AI 超时、无网络等失败路径没有可恢复的 UI。
- 大文本未做长度预算/取消控制，可能导致 API 失败、界面卡死或超额成本。
- 类型通过 `as`/`unknown` 绕过而没有运行时边界验证。

## P2：持续改进

- 可复用的 UI、常量、选择器、格式化逻辑被复制。
- 文案/状态命名混乱，或同一概念有多个名称。
- 无测试覆盖的纯逻辑、无法观测的错误、性能不必要的全量读取。

## 针对本仓库的必查项

1. `src/background.ts` 新增分支是否仅路由；业务是否能下沉到 service。
2. 是否复用了统一正文提取器，而不是新增注入函数或 DOM 选择器副本。
3. 是否读写唯一知识条目模型与统一存储键；导入导出是否包含版本迁移。
4. 页面内 UI 是否能在关闭后还原 `html/body` 样式、移除事件与节点。
5. AI 输入是否截断并清楚提示；输出 JSON 是否做 schema/字段/长度校验。
6. 书签写入前是否有显式确认；批量改动是否有预览、日志和撤销路径。
7. 是否新增或更新了对应的测试，以及 `pnpm typecheck` 和 `pnpm build` 的结果。
